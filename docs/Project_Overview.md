# vision-tracker 项目说明

## 1. 项目要做什么

本项目要实现一个多目标视觉跟踪器。程序每次接收一帧图像检测结果，记录画面中的多个目标，并根据前后帧判断目标的位置、运动速度、当前状态以及下一帧可能出现的位置。

简单来说，它要解决的问题是：摄像头每一帧告诉系统“看到了哪些目标”，系统负责判断这些目标是不是之前见过的、它们如何运动、短暂消失后可能在哪里，以及是否已经真正丢失。

项目主要面向两种目标：普通装甲和旋转装甲。

## 2. 两种目标的区别

### 2.1 普通装甲 `ARMOR`

普通装甲需要跟踪目标编号、坐标、速度、预测位置、当前状态和连续丢失帧数。连续 3 帧没有被观测到后，状态变为 `LOST`。

例如：

```text
帧 0：看到目标 1，状态 TRACK
帧 1：看到目标 1，状态 TRACK
帧 2：没有看到目标 1，丢失 1 帧，仍为 TRACK
帧 3：没有看到目标 1，丢失 2 帧，仍为 TRACK
帧 4：没有看到目标 1，丢失 3 帧，变为 LOST
```

### 2.2 旋转装甲 `SPINNING`

旋转装甲除了位置和速度，还要跟踪当前角度、角速度和预测角度。连续 5 帧没有被观测到后，状态才变为 `LOST`。

例如目标 2 的角度从 `0.0°` 变成 `0.2°`，两次观测间隔为 `0.1 秒`：

```text
angular_velocity = (0.2 - 0.0) / 0.1 = 2.0°/s
```

之后如果暂时没有检测到目标 2，程序仍然可以根据这个角速度预测它的角度。

## 3. 一帧输入包含什么

每一帧由 `InputFrame` 表示，包含帧编号、纳秒时间戳和观测列表。列表中的每个目标由 `Observation` 表示，包含目标编号、目标类型、x/y 坐标和角度。

例如：

```cpp
InputFrame{
    1,
    100000000,
    {
        {1, TargetType::ARMOR, 2.0, 2.0, 0.0},
        {2, TargetType::SPINNING, 5.0, 0.0, 0.2}
    }
}
```

表示第 1 帧检测到了两个目标：目标 1 是普通装甲，位置为 `(2.0, 2.0)`；目标 2 是旋转装甲，位置为 `(5.0, 0.0)`，角度为 `0.2°`。

## 4. 速度和位置预测

速度使用相邻两次成功观测的差值计算：

```text
速度 = 坐标变化量 / 观测时间差
```

例如上一帧位置为 `(1.0, 2.0)`，当前帧位置为 `(2.0, 2.0)`，时间间隔为 `0.1 秒`：

```text
velocity_x = (2.0 - 1.0) / 0.1 = 10.0 m/s
velocity_y = (2.0 - 2.0) / 0.1 = 0.0 m/s
```

下一帧预测位置为：

```text
predicted_x = 2.0 + 10.0 × 0.1 = 3.0
predicted_y = 2.0 + 0.0 × 0.1 = 2.0
```

如果目标暂时没有被观测到，但没有达到丢失阈值，程序继续使用上一次速度预测。例如当前位置为 `x=5.0`、速度为 `3.33 m/s`、帧间隔为 `0.1 秒`，下一次预测位置约为 `5.33`。

## 5. 丢失和重新追踪

目标进入 `LOST` 后，`x`、`y`、角度、速度和预测值都必须清零，但目标对象不能直接删除，因为后续帧可能再次观测到它。

例如目标 1 在帧 12 进入 `LOST`，帧 13 又出现在 `(7.0, 2.0)`：

```text
status = TRACK
x = 7.0, y = 2.0
velocity_x = 0, velocity_y = 0
predicted_x = 7.0, predicted_y = 2.0
missed_count = 0
```

重新追踪的第一帧不使用很久以前的观测计算速度，而是先清零速度。

## 6. 非法帧处理

以下情况必须整帧拒绝：

1. 当前帧号不大于最近一次成功处理的帧号；
2. 当前时间戳不大于最近一次成功处理的时间戳；
3. 目标编号为负数；
4. 同一帧出现重复目标编号；
5. 已创建目标的类型发生变化。

整帧拒绝意味着不修改任何目标、不更新最近成功帧号和时间戳，并返回原有快照。这样可以避免一帧数据只更新了一部分目标。

## 9. 推荐的类设计

### 9.1 `TrackingBase`

这是所有目标的基础类，保存编号、类型、状态、坐标、速度、预测值、角度和丢失次数等共同属性，并提供读取状态、更新基础数据、重置状态和生成 `TargetSnapshot` 等通用操作。基类析构函数应为 `virtual`。

### 9.2 `ArmorTarget`

继承自 `TrackingBase`，专门处理普通装甲：丢失阈值为 3 帧，计算 x/y 速度和位置预测，不处理角度，角度相关字段固定为 0。

### 9.3 `SpinningTarget`

继承自 `TrackingBase`，专门处理旋转装甲：丢失阈值为 5 帧，计算 x/y 速度、角速度、位置预测和角度预测，并在短暂丢失期间继续推进角度。

### 9.4 `TargetManager`

这是项目的核心管理类，负责保存所有目标、校验输入帧、创建目标、更新目标、处理丢失和重新追踪、统计数量以及生成 `Result`。

推荐使用 `std::vector<std::unique_ptr<TrackingBase>>` 保存目标，使容器可以同时管理 `ArmorTarget` 和 `SpinningTarget`。

## 10. 类之间的关系

```text
InputFrame
    │
    ▼
TargetManager
    ├── 校验整帧
    ├── 查找目标
    ├── 创建或更新目标
    ├── 处理未观测目标
    └── 生成 Result
          │
          └── TargetSnapshot
```

继承关系：

```text
TrackingBase
├── ArmorTarget
└── SpinningTarget
```

通俗理解：`TargetManager` 像班主任，`TrackingBase` 是目标通用档案，两个派生类是两种具体目标，`Observation` 是摄像头本帧看到的情况，`Result` 是本帧处理报告。

## 11. 推荐的一帧处理流程

```text
main()
  ├── 创建 TargetManager
  ├── 获取 testFrames() 的 28 帧输入
  ├── 逐帧调用 onFrame(frame)
  └── 使用 printResult() 输出结果
```

目前 `onFrame` 不保存目标、不校验帧、不计算速度和预测，仅返回 `accepted=false` 的空结果。因此当前输出仅能验证程序入口和打印流程，不能验证跟踪功能。

## 12. 核心数据关系

- `Observation`：一帧中的原始目标观测，包含编号、类型、坐标和角度。
- `InputFrame`：帧号、纳秒时间戳和观测列表。
- `TargetSnapshot`：目标管理器对单个目标的当前状态快照。
- `Result`：本帧是否接受、所有目标快照，以及按状态和类型统计的数量。

所有数据类型位于 `namespace rm`。坐标单位为米，角度单位为度，时间戳单位为纳秒，速度根据时间差计算。

## 13. 固定测试帧覆盖的场景

`test_frames.hpp` 的 28 帧数据覆盖创建目标、速度计算、位置预测、旋转角度预测、目标进入 `LOST`、重新追踪，以及重复编号、负数编号、帧号回退、类型变化和时间戳回退等非法输入。

重点例子：帧 0~1 创建目标 1 和 2；帧 6 让目标 2 因连续丢失 5 帧进入 `LOST`；帧 12 让目标 1 因连续丢失 3 帧进入 `LOST`；帧 13 测试目标 1 重新追踪；帧 21~22 测试其他 `LOST` 目标重新出现。

## 15. 最终目标

```text
输入一帧检测结果
    ↓
检查这一帧是否合法
    ↓
更新已有目标并创建新目标
    ↓
处理没有观测到的目标
    ↓
计算速度和预测位置、角度
    ↓
判断是否进入 LOST
    ↓
统计所有目标
    ↓
输出 Result
```

最终系统应做到：看到目标时记录它，暂时看不到时预测它，长时间看不到时标记丢失，再次看到时恢复跟踪，并拒绝可能破坏跟踪状态的非法输入。

## 7. 重点验收场景

1. 普通装甲连续丢失 3 帧后清零并进入 `LOST`。
2. 旋转装甲连续丢失 5 帧后清零并进入 `LOST`。
3. 未观测目标在仍为 `TRACK` 时继续进行位置或角度预测。
4. `LOST` 目标重新观测时恢复 `TRACK`，速度清零，预测值等于当前观测值。
5. 帧号回退、时间戳回退、负数编号、同帧重复编号和类型变化必须整帧拒绝。
6. 被拒绝的帧不能修改目标状态、最近成功帧号或最近成功时间戳。
